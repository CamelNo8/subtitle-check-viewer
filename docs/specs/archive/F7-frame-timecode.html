1. 目的

一覧と CSV の時刻を、SRT の形（00:00:01,000）から「時:分:秒:フレーム」のタイムコード（00:00:01:00）に置き換える。 フレームレートと、ドロップフレーム / ノンドロップフレームを画面で選べるようにする。

2. 決まったこと（質問への回答）

項目決定
方式ドロップ・ノンドロップの両方に対応し、画面で選ぶ。最初の値はドロップ
選択欄の位置画面上の操作欄、YouTube URL の横（設計書どおり）。字幕を読み込む前から選べる
CSV の列足さない（6列のまま）。ドロップかどうかは区切りの「;」「:」で分かる
一覧の時刻開始だけのまま、表示をタイムコードに置き換える

3. 画面

YouTube URL [https://www.youtube.com/watch?v=...]   fps [29.97 ▼]  方式 [ドロップ（;） ▼]
  • fps の選択肢: 29.97 / 30 / 23.976 / 24 / 59.94（設計書どおり、最初は 29.97）
  • 方式の選択肢: 「ドロップ（;）」「ノンドロップ（:）」。最初は「ドロップ（;）」
  • ドロップフレームがあるのは 29.97 と 59.94 だけ。それ以外を選んだときは方式を「ノンドロップ（:）」にして選べなくする（灰色）。29.97・59.94 に戻したら、前に選んでいた方式に戻す
  • 選び直すと、一覧の開始時刻がすぐ書き換わる。一覧は作り直さないので、入力中のコメント・スクロール位置はそのまま
  • 選び直しは「コメント・修正案の変更」ではないので、ページを閉じるときなどの確認（F6）には影響しない
  • 選んだ値はページを開き直すと最初の値に戻る（設計書: ブラウザへの自動保存はしない）

4. 計算の決まり

  1. ミリ秒 → フレーム番号: 実際のフレームレートで割り、一番近いフレームに丸める（設計書どおり。ちょうど半分は切り上げ）。
    29.97 = 30000/1001、23.976 = 24000/1001、59.94 = 60000/1001 として計算する（29.97 と書いても本当は 29.97002… のため）
  2. フレーム番号 → タイムコード（ノンドロップ）: 1秒を 30 / 24 / 60 フレームとして数える。
    そのため 29.97fps では、本当の時間より少しずつ遅れて表示される（1時間で約3.6秒）。これはノンドロップの決まりどおり
  3. フレーム番号 → タイムコード（ドロップ）: ずれを直すため、毎分の最初の番号を飛ばす（29.97 は 2つ、59.94 は 4つ）。ただし 10分ごと（0, 10, 20…分）は飛ばさない。
    例: 29.97 で 00:00:59;29 の次は 00:01:00;02（;00 と ;01 は使わない）
  4. 書き方: 時・分・秒・フレームを2桁で書く。区切りはノンドロップが「:」、ドロップは最後だけ「;」（00:01:00;02。業界で一般的な書き方）

7. 変わるところ（他の部品）

  • buildReviewCsv(subtitles, reviews, setting): 開始時刻・終了時刻をタイムコードで書く。タイムコードには「,」がないので、時刻の欄は " で囲まれなくなる

  • updateStartTimes(tableBody, subtitles, setting)（新規）: 一覧を作り直さず、開始時刻の文字だけ書き換える
  • CSV の読み込みは番号で合わせるため変更なし。F6 で書き出した CSV（SRT の形の時刻）も読み込める
